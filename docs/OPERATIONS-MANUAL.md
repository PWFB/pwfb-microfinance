# PWFB Microfinance — Operations Manual

## 1. Purpose

This manual describes the standard operating workflow for the PWFB
Microfinance administration dashboard.

All operations should be performed by authorized personnel and recorded
accurately.

## 2. Administrator Login

1. Open the PWFB Microfinance administration portal.
2. Navigate to the login page.
3. Enter the authorized account credentials.
4. Authenticate successfully.
5. Confirm that the correct dashboard and permissions are displayed.

Never share administrator credentials.

## 3. Dashboard

The Dashboard provides the primary administrative overview.

Administrators should use it to:

- Review operational information.
- Access major modules.
- Monitor current activity.
- Navigate to required workflows.

## 4. Customer Operations

### Add a Customer

1. Open **Customers**.
2. Select the customer creation option.
3. Enter the required customer information.
4. Review the information for accuracy.
5. Save the customer record.
6. Confirm that the customer appears in the customer list.

### View a Customer

1. Open **Customers**.
2. Locate the customer.
3. Open the customer's record.
4. Review the available information.

### Edit a Customer

1. Open **Customers**.
2. Locate the customer.
3. Select **Edit**.
4. Update the required information.
5. Review the changes.
6. Save the record.

Customer information should be kept accurate and current.

## 5. Savings Operations

Savings operations should be performed against the correct customer and
account.

Before processing a savings transaction:

1. Confirm the customer's identity.
2. Confirm the correct account.
3. Confirm the transaction amount.
4. Review the transaction details.
5. Submit the operation.
6. Confirm that the transaction was recorded correctly.

## 6. Loan Operations

### Create a Loan

1. Open **Loans**.
2. Select the loan creation option.
3. Select the appropriate customer.
4. Enter the required loan information.
5. Review the loan details.
6. Submit the loan.
7. Confirm the resulting loan record.

Loan approvals should follow the institution's applicable credit procedures.

### Review a Loan

1. Open **Loans**.
2. Locate the loan.
3. Open the loan record.
4. Review the principal, status, repayment information and other available
   details.

## 7. Repayment Operations

Before recording a repayment:

1. Confirm the customer.
2. Confirm the loan account.
3. Confirm the repayment amount.
4. Verify the payment information.
5. Record the repayment.
6. Confirm that the loan balance or repayment history reflects the operation.

Incorrect repayment records should be escalated to authorized personnel.

## 8. Transaction Operations

Transactions must be entered carefully.

Before saving a transaction:

- Confirm the customer or account.
- Confirm the transaction type.
- Confirm the amount.
- Confirm the transaction date.
- Review all entered information.

Financial transactions should not be altered without proper authorization.

## 9. Banking Operations

Finance Operations may include:

- Deposits.
- Withdrawals.
- Transfers.
- Customer wallet selection.
- Deposit fund management.

Every banking operation should be verified before submission.

## 10. Staff Operations

Authorized administrators can manage staff information.

When creating or updating staff records:

1. Confirm the staff member's identity.
2. Enter accurate staff information.
3. Assign the appropriate role.
4. Confirm employment status.
5. Review the record.
6. Save the changes.

Access should be removed or restricted when a staff member no longer requires
system access.

## 11. Branch Operations

Branch information should be maintained accurately.

Administrators should review:

- Branch identity.
- Branch status.
- Operational assignments.
- Staff assignments where applicable.

## 12. Reports

Reports should be used to review operational and financial activity.

Before relying on a report:

1. Confirm the reporting period.
2. Confirm the selected filters.
3. Review the results.
4. Investigate unusual figures.
5. Export or record information only through approved procedures.

## 13. Daily Administrative Review

At the end of an operational day, authorized administrators should review:

- Customer activity.
- Savings activity.
- Loan activity.
- Repayments.
- Transactions.
- Banking activity.
- Staff activity.
- Operational reports.

Unusual activity should be investigated promptly.

## 14. Error Handling

If an incorrect operation is identified:

1. Do not create additional transactions simply to hide the error.
2. Record what happened.
3. Identify the affected customer or account.
4. Notify the appropriate authorized administrator.
5. Correct the issue through the approved process.
6. Preserve relevant records for audit purposes.

## 15. Session Security

When finished using the dashboard:

1. Save required work.
2. Review important operations.
3. Sign out.
4. Close the browser when using a shared device.

Never leave an administrative session unattended.

## 16. Production Changes

Operational users must not modify production application code.

Production code changes should follow the development workflow:

1. Modify locally.
2. Test.
3. Build.
4. Review Git changes.
5. Commit.
6. Push.
7. Confirm deployment.
8. Verify production.

## 17. Principle of Accuracy

Financial and customer information must be entered accurately.

Before confirming any important operation, verify:

- Customer.
- Account.
- Amount.
- Transaction type.
- Date.
- Status.
